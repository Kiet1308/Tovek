# Static module naming summaries

`scripts/module_summaries.py` analyzes a project under an explicit manifest of module IDs, source hashes and script-node paths. It uses the pinned official Luau parser and never executes require, writes source or invokes a model. The manifest is part of the result identity.

The resolver follows only literal script property paths (including Parent) to a unique declared node. Dynamic indexing, missing targets, duplicate paths, rebound import bindings, local shadowing of require and observable environment rebinding remain unknown. Direct return-require aliases are tracked. A module's dependency SCC records possible static dependencies, not a promise that all those calls execute or that a require cycle loads successfully.

Exports are restricted to an immutable function binding, a returned function, a static forwarding alias, or a private literal table with distinct literal keys. A table that escapes, is mutated, or is observed before return is refused. Conditional module builders, metatable exports, indirect aliases and dynamic field dispatch remain unknown. This explicit refusal covers many public OOP modules.

Each function has a module-qualified identity and observed parameter declarations. A straight-line scalar return tuple can describe local/field roles. A fixed-arity forwarding call inherits an already available result summary, preserving the origin function's identity. Open packs, variadic functions, branching return shapes and unresolved forwarding cycles do not get guessed summaries. Eight simultaneous propagation rounds and bounded alias resolution prevent recursive expansion. Calls inside nested functions are owned by the nested function. Argument-role candidates require fixed exact arity and retain both the argument binding and callee parameter identity.

Names are observed input identifiers or inferred roles. Static path resolution assumes the operator-supplied script tree and conventional module lookup; it does not prove the runtime identity of require, a module export or a callee. No type, alias, purity, throw, yield, load-order or ownership certificate is produced. These summaries are optional metadata and do not automatically rename decompiler output.

Limits are 2,000 modules, 512 KiB per source, 64 MiB project source, 100,000 analysis units per AST walk, two million project AST dictionary nodes, depth 128, 32 return slots and eight propagation rounds. Output reports unresolved return summaries and whether the propagation-round limit was reached. Source hashes and parser hash pin each run.

The [public context manifest](module_source_corpus_v2.json) explicitly assumes a filesystem mirror inside each repository, with init.lua/luau owning its directory node. It is an analysis context, not a verified Roblox deployment or Rojo mapping. Unlisted dependencies remain unknown. The nine small fixture modules use a separately declared tree; their manifest locks forwarding origin, cycle, mutation, shadowing and escaped-export expectations.

CI runs unit controls, the real-parser fixtures and all 171 public sources. [Per-file public results](roadmap_v2_acceptance/module_public.json), [fixture results](roadmap_v2_acceptance/module_fixtures.json) and [repeat/cost records](roadmap_v2_acceptance/module_validation.json) are archived. The source analysis cost is separate from decompiler throughput, and these results do not claim an improvement in inferred-name quality.
