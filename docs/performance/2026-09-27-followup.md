inputs, potentially 10x**, and authorizes architectural rewrites. That target is
**not achieved**. Main now contains validated wave 7. Four balanced independent

allocation reduction is not a speed percentage. W7 passes 1,279 workspace tests,

multiply ratios from different cohorts. Cache ablations now show workload

The 3x–5x target remains unmet. Full evidence
is in [`2026-09-27-ultra-wave7.json`](2026-09-27-ultra-wave7.json), with earlier

## Changes implemented

| Area | Removed work | Invariant retained |
|---|---|---|
| SSA renaming | Rebuilding the full mutable read/write list for each operand | Lookup order, local IDs, duplicate destinations, recursive closure write-before-read |
| SSA sealing | Polling all pending blocks after each DFS visit | Exact first-ready event and original DFS tie order |
| SSA definitions/captures | Reinserting cached definitions; collecting locals when no reference cell is open | Complete definition maps, capture groups, CLOSE provenance |
| CFG edge queries | Allocating a vector merely to check one/two outgoing edges | Exact cardinality, tags and parallel edges |
| Logical normalization | Flattening logical trees into vectors and allocating replacement boxes | Operand order, exact normalized shape, diagnostic origin policy |
| Table reconstruction | Repeated unsuccessful declaration-run scans and moving the entire suffix twice | All motion/dependency/effect checks and their proof budgets |
| Lifting | Register hashing, redundant literal cache copies, temporary template/range/PC vectors, unused closure-site strings | Lazy local creation order, literal bits, debug/types/provenance |

Sealing computes each non-entry block's event as the maximum of its own DFS rank
and its predecessor ranks. Two dense arrays retain ordered linked event lists;
the graph topology is fixed during SSA construction. Schedule construction and
consumption visit O(V+E) graph elements, with expected constant-time rank lookup.
The change does not make every operation in SSA linear.

Read replacement now traverses a statement twice instead of once per read.
Statements without local reads skip the second traversal. DFS rank lookup uses
an FxHasher-backed ordered set; iteration remains the original DFS order.
Write replacement similarly publishes the precomputed versions together.
Logical reassociation rotates the existing tree into a left spine in O(nodes)
time with no new operand boxes or auxiliary traversal vectors. Table sinking
still has worst cases involving repeated dependency checks; only the documented
redundant scans and suffix shifts are removed.

No reconstruction pass, proof check, naming policy, numeric assumption or output
quality option is disabled. This change adds no unsafe Rust.

## Remaining priorities

These are findings and proposed next steps, not implemented speedups. None has
a justified whole-engine speedup estimate yet.

1. **Reuse AST usage analysis within a phase.** `inline_temps`, `copy_cleanup`
   and `conditional_expressions` repeatedly build descendant-inclusive maps at
   ancestor blocks. Bottom-up summaries with incremental invalidation can remove
   work proportional to nesting depth. Summaries must distinguish descendant
   reads, current-function reads, actually executed reads and Copy/Ref captures.
   Start with one phase and compare every accepted rewrite against its existing
   implementation before sharing data across phases.

2. **Make SSA expression normalization incremental.** `cfg/src/ssa/inline.rs`
   restarts consumer scanning and calls full expression reduction after each
   successful substitution. Wide calls or growing expressions can revisit the
   same subtrees repeatedly. Track changed operands and normalize their ancestors
   while preserving candidate order, multi-return behavior and effect barriers.
   A global pass reorder or reduced iteration budget would change the contract.

3. **Separate local identity from allocation ownership.** `RcLocal` carries
   `Arc<Mutex<Local>>`; many passes allocate maps, clone handles and lock metadata.
   A compact per-function local index plus metadata arena could improve data
   locality across many phases. First replace `name_one`'s `Arc::count == 1`
   unused-local heuristic with explicit facts. Cross-function captures, published
   closure bodies, source bindings and deterministic mint order need an explicit
   ownership model. Stable IDs use large disjoint ranges, so indexing a vector
   directly by `stable_id()` would be incorrect; use compact ordinals.

4. **Fuse read-only naming censuses.** `name_locals` separately collects aliases,
   usage, counts, collapse candidates, class and collection evidence. A shared
   census should store identities, not extra owning local handles, and retain
   existing candidate precedence. `refine_names` could construct witnesses only
   when they are retained and propagate changed facts rather than all candidates.

5. **Update large destructor classes incrementally.** Congruence-class merges
   invalidate binding summaries and refresh equal-ancestor data across members.
   Small-to-large updates or dirty-member tracking may avoid growing rescans.
   Preserve member-key replacement behavior, refusal state, source-binding
   compatibility and the interference proof. Measure class-size distributions
   before accepting extra indexing overhead on ordinary small functions.

6. **Cache structural facts only after defining mutation boundaries.** The
   structurer retains per-loop reverse reachability and dynamic closure-body
   queries. An SCC/reachability index needs a memory budget. Closure answers cannot
   be cached across another worker publishing the body without a revision or
   immutable publication boundary. Existing capture checks deliberately remain
   dynamic for this reason.

7. **Prototype templates and bytecode string ownership.** Repeated closure
   occurrences are lifted independently. Immutable templates could share analysis,
   but each occurrence still needs exact capture context, local remapping and
   provenance. Borrowed/shared bytecode strings could remove parser-to-AST copies;
   this crosses lifetime and public representation boundaries.

Smaller remaining candidates include the De Morgan simplifiability ancestor
rescans in `normalize_conditions`, eager phi dependency graphs, batched local
declaration insertion, source-line decoding, prototype-DAG validation and Worker
batch duplicate sharing. Lua 5.1 register-map iteration currently influences
initialization order, so the Luau dense-register change cannot simply be copied.

Release settings already use optimization level 3, fat LTO, one codegen unit and
mimalloc in native binaries. Panic unwinding is required for recovery. Existing
PGO measurements belong to older code and need retraining and fresh validation;
they are not additive to this comparison. Raising thread count also does not
remove serial work within a large individual function or the final AST passes.

The highest-value next architectural experiment is a phase-local fact context,
followed by compact local storage after naming no longer depends on reference
counts. Both should be introduced behind differential validation, one consumer
at a time, with identical output and measured allocation/runtime gates.

### First implementation wave (validated and measured)

- U01: an exact-order dirty-block schedule skips unchanged SSA inline visits;
  the dead-assignment and table-folding sweeps and their fixed-point termination
  stay unchanged. A lazily built identity-to-block dependency index propagates
  usage-count changes. New diagnostic counters expose index cost and skipped
  statement visits; the test oracle compares intermediate sweeps, phi edges,
  legacy usage counts, identities, origins and inline events.
- U02/U09: temporary inlining indexes local occurrences by subtree intervals,
  storing numeric IDs without retaining owners. Successor deletion skips removed
  occurrences; shared bodies and unusual indexed-LHS closures use the original
  census. Goto absence propagates only through covered statement kinds. Ordinary
  inline no longer constructs numeric facts used exclusively by UI rebuilding.
- U03: write/mutable-write visitors preserve order and duplicate slots, including
  the intentional GenericForNext control exclusion. SSA inline facts, def/use
  and liveness consume visitors instead of intermediate local vectors.
- U04: conditional changes distinguish expression/branch-tag edits from graph
  adjacency changes. The former keep the same outer iteration but retain valid
  dominators. Other transforms conservatively invalidate them.
- U05: Boolean capture queries short-circuit without materializing captured-local
  sets. Each query still observes current locked bodies; every site's upvalues
  precede its shared-body recursion guard. No cross-publication cache is added.
- U10: naming report strings/type evidence/status maps are built only when a
  report is requested. Four synchronous propagation rounds keep original edge
  order and candidate caps while skipping sources unchanged since the last round.
  Seeded reference comparisons include conflicts, cycles, caps and witnesses.
- U11: source-line decoding streams wrapping prefix sums into one output vector,
  preserving missing metadata and overflow behavior without two scratch vectors.

These are experimental until the source-pinned release passes output, semantic
and performance gates. Test-only reference implementations are retained; neither
diagnostic phase timings nor constructed scaling tests establish corpus speedups.

### Third-wave prototypes and remaining architectural decisions

An isolated source copy allowed these third-wave prototypes while second-wave
binaries and ablation variants remained pinned. They were subsequently promoted
and measured as documented below:

- U01/U03: direct operand/root visitors and reuse of single-RHS observability.
- U07: sorted per-local last-use vectors, checked against the old hash maps.
- U04: borrowed structural-match conditions/argument values, cloning on success;

- U08: consume statements already copied by canonicalization instead of copying

- U16: batch declaration insertions so each original statement moves at most
  once; traverse connection-analysis child blocks by borrow instead of cloning
  them; omit provably duplicate NEWCLOSURE graph edges after the same validation.

that path has one decoder consumer, reconstruction. The other consumers are gated
by upvalue-analysis/provenance options. Sharing could reduce repeated work in
artifact mode, at the cost of retaining all prototype line vectors; it is not a
cold-engine speedup and is deferred without an artifact-specific memory study.

timing of topology/local-map/edge-tag changes is observable to later matching.

or arena conversion remains rejected: naming/unsharing observes ownership, child

### Next representation experiment: identity-only SSA scratch tables

The next bounded architecture pilot is numeric stable-ID keys in SSA read-count,
definition/last-use and private liveness membership tables. `RcLocal` equality
and hashing already use its stable ID without locking metadata; the proposed
change would remove temporary atomic owner traffic and shrink keys, not remove
AST traversal or metadata locking. Shared AST/function handles must remain:
function bodies are published by parallel workers, and naming observes local
owner counts. A global Arc-to-Rc or arena substitution is not justified by the
current profile. This pilot has not been implemented or assigned a speedup.

An independent census should also compare Destructor's constructor-time local
reserve against entries surviving SSA cleanup. Lookup-only table reserve may be
adjustable; value-class/congruence-table iteration participates in tie choices,
so changing all reserves can alter output. The experiment must preserve exact
hash/insert behavior, minted IDs and owner-sensitive boundaries, with a separate
legacy oracle and measured baseline. The external design and source references
are archived in `wave8-representation-plan.md` beside the frozen experiments.

## Structural investigation after the W7 checkpoint

W7 is committed as `c0ca44b` on `perf/ultra-decompiler`. The quality floor is
unchanged: a faster algorithm must preserve or improve semantics and readability,
with all requested reconstruction and metadata. Experimental rewrites remain
isolated; diagnostic results are not advertised as an engine speedup.

A light, feature-only census validates all **3,978 source hashes** and records
1,106,751 rows without dropped or misnested spans. Its 17 new focused tests pass.
The frozen release source and corrected test source differ only in two test-only
compile fixes; no additional release rebuild was needed. Full evidence is in
[`2026-09-27-ultra-wave8-census.json`](2026-09-27-ultra-wave8-census.json).

The lifter adds an empty synthetic entry to every function. Consequently, zero
initial one-node functions does **not** mean zero logically straight-line bodies.
Using the proven two-node/one-edge minimum identifies 13,835 such functions.
Their construction + inlining + destruction account for 9.717% of diagnostic
elapsed time, or 9.582% after removing explicit census spans from numerator and
denominator. Additional instrumentation overhead remains. Excluding CLOSE leaves
13,357 functions and 8.974% census-adjusted exposure. These are cost ceilings,
not speedup estimates or capture/source-binding safety certificates. An isolated
single-body rewrite is therefore not the next multiplier experiment.

The next bounded hypothesis removes temporary SSA phis across eligible blocks,
rather than merely accelerating their allocation: the current constructor seals
a block after visiting it even when its single predecessor has already been
processed. A default-off experiment will test earlier sealing under conservative
capture, metadata and graph guards. It may change incidental local identities;
final semantics and readability remain mandatory. No benefit is established yet.
A separate count-only probe checks repeated processing of growing expressions.

The older `MEDAL_PROF` timers were also audited. Deinline prints its own cumulative
counters *inside* the enclosing timer, so the observed 5.190 seconds includes
logging. That diagnostic is retained with an explicit contamination note and is
not used to assign whole-engine cost or claim a deinline bottleneck. No second
run was performed merely to repair its reporting assertion.


## Early SSA sealing: rejected after a bounded experiment

The default-off early-sealing prototype is **not promoted**. Six focused
construction oracles pass after explicitly proving and projecting trivial phi
aliases; the original failed intermediate-shape assertion and a separate
incorrect one-to-one forwarding-count assumption remain archived. The AST suite
passed 882 tests. These checks did not establish whole-pipeline quality.

The release screen has 3,948 exact sources and 30 changed sources, with no CLI
failures. All 60 changed baseline/candidate sources compile. Manual review finds
mostly equivalent simplifications and naming changes, but one new parameter
assignment is a presentation concern. More decisively, the prototype's provenance
guard makes `--emit-binding-provenance` restore the old source body while ordinary
and upvalue-analysis modes emit the new one. This violates source-mode parity.
Original bytecode confirms the reviewed vector fallbacks are LOADK vector
literals; they are not newly assumed truthy calls to an arbitrary global.

A small exploratory ordinary-build screen was used only to decide whether more
work was warranted. It kept separate **unaccepted** candidate expected hashes;
accepted baseline goldens were never changed. Four paired processes per thread
count used the same 3,350 distinct inputs, balanced order and separate first
calls. Repeated-call means were W7 **8.0569s / 0.7303s** versus candidate
**8.8390s / 0.7765s** at one/16 threads. Candidate's 11.0578s sample is retained;
medians also fail to show improvement (**8.0788s / 0.7146s** versus
**8.1569s / 0.7573s**). No further build or broad validation is justified for this
narrow prototype. This does not disprove every possible SSA redesign.

The next scoped change targets a separately demonstrated repeated-copy cost.
Accepted 64-step initializer chains create final trees of 65/129 RValue nodes
while copying 2,144/4,224 nodes. Existing depth guards are unchanged and cap
longer chains. This is a count result, not a whole-engine speedup. A minimal
ownership transfer at the already-approved substitution leaf is being tested,
retaining all safety/readability decisions and truthful moved-node ancestry.
