TovekV2: A new generation of decompilation

A new perspective on compiled code
September 19, 2026Development previewV0.9 → V2

A new generation
of decompilation.

Introducing Tovek V2. Clearer code, stronger foundations, and a closer connection to the program underneath.

Explore Tovek V2 ↗

Today, we’re introducing Tovek V2: a substantial rebuild of how Tovek reconstructs, explains, and checks decompiled Luau.

Since v0.9 beta, 130 commits have changed the path from bytecode to readable code. V2 recovers more useful names and types, rebuilds loops and UI trees, and tracks the relationships between the input and the final output. Underneath those visible improvements is a stricter treatment of evaluation order, closure identity, and multiple returns.

The aim is simple: help you understand the program. That means making code clearer while retaining the details that affect what it does.

Code that tells you more.

A useful name can turn an anonymous value into a recognizable role. V2 combines retained bytecode information with evidence from field access, argument positions, API usage, branches, and returned tuples. That lets an otherwise generic pair become width, height, a Fusion callback become processor, or a buffer-growth parameter become size.

Recorded debug names take priority. When the input contains type information, V2 can restore supported parameter annotations such as number, string?, Vector3, buffer, and named host types. Missing type spellings stay unknown. Inferred roles carry confidence and competing evidence, reducing misleading collection names and awkward forms such as serializeds.

V2 also preserves meaningful binding boundaries through SSA transformations. A result selected between parameters can retain its own local when it is both observed and returned. Recorded source intervals, captured storage, and stronger names remain protected. The change is deliberately selective: normalizing an optional argument does not automatically create another variable.

A stronger foundation for every transformation.

The control-flow engine now reconstructs source-like loops using explicit ownership, edge-transfer, iterator-protocol, and close-event checks. Shared continuations can be emitted once after a branch. Loop initialization stays in the right place, and captures retain the correct storage cell across iterations. The previous structurer has been removed.

Correctness fixes reach beyond loops. V2 protects global and field lookup order, the order of equality metamethod arguments, repeated index evaluation, nested assignment addresses, and reads of mutable captured values. It also preserves trailing nil values and the exact number of results from calls and varargs.

These details can be observable. Moving a field lookup across a call may change which value is read—or which error happens first. V2 retains a snapshot when a transformation cannot justify that move.

Across the 198 runtime profiles shared with beta, v0.9 passed 138 and diverged in 60. V2 passed all 198. The expanded V2 suite now passes 246 profiles.

Short terminal branches can now become direct returns or compact scalar guards when their values and evaluation order are exact. A call that originally contributed one result still contributes one result. Default output continues to favor clear statements over nested if-expressions.

From scattered assignments to coherent structures.

Optimized Luau can spread a single UI tree across temporary factory handles, property writes, callbacks, and list-packing code. V2 brings eligible regions together into nested constructors, including curried factories and dynamic event keys.

The reconstruction follows the order of each observable operation. A table can absorb initialization before its first capture or observation; initialization that is already visible to another part of the program stays in place. Nil overwrites, dynamic keys, and multiple-return tails retain their behavior.

The final corpus contains zero adjacent single-use require-to-field relays recognized by the scanner. The broader constructor pass groups related component exports inside their table. Named imports used as meaningful callees remain useful and are preserved.

Recover the shape. Respect the evidence.

V2 extends de-inlining for bounded named arithmetic helpers and scalar regions. Candidate helpers survive long enough to be compared with the code that may have come from them. Each replacement checks the helper body, arguments, capture behavior, and result arity; a familiar API name is never a purity guarantee.

Completed numeric values enable narrow arithmetic cleanup, including results already produced by a length operation. Recursive callees installed in a proven stable pattern can lose redundant aliases. Where a snapshot still needs to remain, late naming can expose its purpose as midpoint, midpointX, or halfSegCount.

  • Helper placement: eligible single-use helpers can join a constructor that already mixes inline callbacks and named helpers. Uniform helper lists remain separate.
  • Wide expressions: group-aware formatting reduces long lines without changing the parsed expression.
  • Unused checks: discard cleanup removes only expressions whose effects are proven safe to discard.
  • Optional synthesis: bounded arithmetic loop synthesis stays opt-in and is identified separately from recovered calls.

These are targeted improvements. Geometry and prettyPrint still contain more intermediate steps than beta. The arithmetic fixes improve some expressions and names; they do not recover every original formula or function boundary.

Look behind the output.

V0.9 introduced static upvalue sidecars. V2 expands that foundation into optional binding provenance, input-node and statement ancestry, conditional lineage, lexical declarations, and exact emitted identifier spans. Tools can follow an output token to its binding and the available input evidence.

Recorded facts, inferred roles, reconstructed calls, and synthesized elements are kept distinct. Unknown origins remain unknown. These diagnostics support inspection without presenting a guessed name or a convenient helper as proven original source.

Compact annotations are also optional. They shorten recognized comments while retaining the complete text in provenance sidecars. If metadata cannot retain the text, the formatter falls back to the full comment. Default output keeps full diagnostics.

An independent offline source registry can identify matched upstream source against pinned, licensed entries and exact execution images, followed by recompilation. This is explicitly labeled source lookup; it is not a claim that comments or stripped names were recovered from bytecode.

A local tool, with room to inspect.

The Rust CLI continues to handle single files and complete folders. V2 adds an optional bounded artifact cache that accounts for the executable, bytecode, options, and naming context. Path-specific metadata is regenerated, and cache integrity is checked before reuse.

Performance work includes cached SSA statement facts, bounded common-tail rescans, pass-level profiling, and separate CLI, in-memory API, and allocation measurements. PGO was evaluated in isolation. Further performance tuning remains deferred; historical warm-cache results are not advertised as a general V2 speedup over beta.

Core decompilation runs locally using deterministic rules. AI is disabled by default, and the current implementation does not load or download models or call AI services.

Choosing a workflow

Tovek provides source you can build and a local CLI you can inspect. lua.expert’s documented interface is a hosted API that accepts base64 bytecode and returns Luau text. This is a deployment distinction, not a quality ranking. We have not run a fresh, matched V2-versus-lua.expert evaluation for this release article.

Of the 405 measured public profiles, raw structural similarity improves in 217, declines in 59, and is unchanged in 129. The normalized comparison records 215 improvements, 61 declines, and 129 unchanged. Better averages do not erase those regressions.

The 513 public profiles come from 171 source files at O0/O1/O2. Three optimization profiles are not three independent programs. Private coverage includes 3,936 nonempty inputs and 42 empty inputs; the private game was not executed as a complete Roblox experience.

Validation includes 1,050 primary workspace tests, one child-test repeat, and 126 Python tests. Parser, compiler, runtime, metadata, thread determinism, and output-quality checks answer different questions. Neither a successful recompile nor a structural ratio proves general semantic equivalence.

Bytecode does not uniquely determine the original source. Stripped names, comments, erased types, and many author choices cannot be recovered with certainty. V2 makes the remaining evidence more useful.

Availability.

Tovek V2 is available as a development preview on the roadmap-v2 branch. Build it with the pinned Rust toolchain below. The latest tagged binary remains v0.9.0-beta; a V2 binary release has not been published as part of this announcement.

Run target/release/luau-lifter (or target\release\luau-lifter.exe on Windows) with your bytecode file. For a folder, use decompile-folder <input> <output>. Folder mode defaults to Roblox’s encoding key 203; raw single-file mode uses unencoded bytecode unless specified.

Visit the usage guide for encoded files, output extensions, analysis sidecars, cache options, and the local server. Tovek is MIT licensed and builds on the work of the medal project.

Sources and methodology.

This article summarizes the complete development range from 27422b9 (v0.9.0-beta) to 465c9dc. Feature descriptions were checked against implementation contracts and acceptance records, not inferred from commit counts alone.

  1. Final delivery acceptance: exact build identity, comparison measurements, test scope, report hashes, and remaining limitations.
  2. V2 implementation record and output-fix record: per-stage results, optional modes, historical measurements, and proof boundaries.
  3. Owned regression fixtures and pinned public-source manifest: reproducible inputs and provenance. Private source and output remain local.
  4. lua.expert API documentation, checked September 19, 2026, for the hosted-interface description. No comparative quality or speed claim is derived from that page.
