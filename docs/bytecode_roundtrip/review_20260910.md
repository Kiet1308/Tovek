## SETLIST triage and the bugs caught by runtime fixtures

Late UI rebuilding removes 37 of the previous 59 SETLIST fallbacks. The remaining
22 sites use a counted `table.pack` loop. This fixes the old sparse `next` loop:
nil results must overwrite existing slots, and every fixed value and the final
multret expression must be evaluated before any slot is written.

The triage classifier recognizes only a lost multret SETLIST plus the complete
added pack/count/numeric-loop/copy instruction group with its exact starting
index. Missing counts, wrong offsets and unrelated calls stay visible in unit
tests. This classification does **not** alter signature equality, prototype
counts or baseline acceptance; `raw_delta` is retained in reports.

`ui_setlist_order` also caught premature SSA folding of a captured table cell:
the callback saw nil because the table assignment had been postponed. Captured
cells now retain their original assignment and field-store sequence. Additional
checks cover dynamic-key errors, placeholder replacement order, one-result
factory handles, skipped calls, numeric-key overlap and nil/multret tails.

The UI pass briefly exposed another growth bug: guard flattening duplicated an
entire UI constructor because it occupied one `return` statement. Guards now
have an expression budget and never duplicate tables or closures. The extra
`Base/Image` prototype/size regression was fixed before refreshing baselines.
