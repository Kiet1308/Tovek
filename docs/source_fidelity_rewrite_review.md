# Anonymous returns and repeated-literal hoisting

This R6 review distinguishes retaining recorded source information from
introducing a useful name. It does not infer a source declaration from repeated
bytecode constants or from an unmapped binding.

## Anonymous returns

The R1 policy remains appropriate: preserve a valid compiler-recorded function
name as a named declaration and reference, including a single return or callback
use. `inline_temps::is_generated_temp` excludes any local with `SourceBinding`;
`inline_once` also checks this evidence independently of the emitted spelling.
Its narrow exception, `assignment_preserves_function_name`, applies only to a
same-named field/global definition and only when all evidence is function-name
evidence. A recorded debug local does not qualify, even with equal spelling.

Consequently, `local function invoiceTotal(...) ... end; return invoiceTotal`
and `createElement` retain their recorded identities. Anonymous closures with
no recorded binder can still be emitted directly. Inventing a binder for every
anonymous return would add syntax without recovering evidence. The existing
[gallery](roadmap_v2_gallery.md) and binding-aware corpus contracts cover these
decisions; this change does not relax their guards or claim new name recovery.

## Rehoist: synthesis with a register constraint

The old pass already required at least three matching **syntactic role/literal**
occurrences in one function scope. Raw frequency alone was insufficient. The
recognized roles are `task.wait`'s first argument, `task.delay`'s first argument,
literal magnitude-comparison thresholds, and selected asset-id property stores.
The two call roles remain distinct; closure bodies are counted separately.

These roles suggest names, not the author's original declaration or intent.
For example, `DISTANCE_EPSILON` is a small-positive-threshold naming heuristic,
not a proved tolerance. `task.wait` spelling does not establish API identity or
purity. Only an immutable literal moves to the function head: each original
lookup, call, condition, property-address evaluation and store stays in place.
Finite numbers retain their exact bit pattern, including signed zero; strings
retain their bytes. Name reservation includes parameters, local/global uses and
descendant functions, so a new local cannot capture an existing global use.
No source/debug identity, SSA lineage or lifetime certificate is attached to
the new local. Explicit early-pass producer metadata remains R2 work.

The review found a reproducible compiler failure in the previous local-only
budget. An AST function with 180 parameters, three `task.wait(1)` calls, three
`task.delay(2, callback)` calls and a 73-argument `sink` call compiles with the
pinned Luau compiler at O0. Inserting `WAIT_INTERVAL` and `DELAY_DURATION` makes
it fail: allocating 74 registers at the call exceeds the compiler's 255 limit.
The source and failing rewrite come from the actual pass-boundary example,
not a decompiler roundtrip that might simplify the witness away.

The pass now uses the existing conservative emitter frame estimate: parameters
and declarations, hidden numeric/generic-loop registers, and expression/call
scratch. It limits introduction to the smaller remaining allowance under 192
locals and 240 estimated registers. Disjoint scopes count together. Opaque
SETLIST/internal control gives no introduction headroom. A shared preflight
checks at most 200,000 nodes and depth 128 before recursive cost analysis and
mutation; budget failure leaves the source tree alone. This is a conservative
refusal policy, not a model of every future compiler or a proof for arbitrary
later rewrites. It narrows hoisting rather than adding new roles or motion rules.

## Independent controls and limits

Run the native fixtures and the pinned parser/compiler/VM audit with:

```text
cargo +nightly-2024-12-15 run -p luau-lifter --example rehoist_constants -- FRESH
python scripts/rehoist_audit.py --fixtures FRESH --lifter LIFTER --compiler LUAU_COMPILE --luau LUAU --ast LUAU_AST --report REPORT.json
```

Ten cases cover register/local pressure, hidden loop registers, ordinary call
roles, branch evaluation, signed zero, distinct roles, descendant globals,
separate closure scopes and asset-property byte/store ordering. Each runs at
O0/O1/O2 and g1/g2 with `--fflags=false`: 60 configurations, each with 26
flag/error-injection vectors. All compile, parse and preserve observations.
Twenty controls pass: two O0 profiles reject the exact old register-overflow
rewrite; eighteen compiled mutants expose shadowed globals, erased negative
zero or moved global-field lookups. The old pass's emitted witness is byte-for-
byte identical to the register mutant generated by the audit.

The same witness also reproduces through the full decompiler pipeline: the
preceding release emits source that fails O0 recompilation; the new release
compiles. The optional `--lifter` gate runs all six input compiler profiles,
checks output recompilation and the same VM vectors, validates provenance, and
compares full source/metadata at one and four threads. CI enables this gate.

The bounded dataflow checker proves 58 configurations and reports `different`
for signed zero at O0/g1 and O0/g2. Those two results remain `different`; VM
observations, reciprocal-zero checks and the zero-erasure controls are separate
evidence, not a reason to promote the dataflow result. This suite makes no claim
about source-level debugger introspection, allocation failure, real Roblox API
implementations, or recovered author constant names.

## Corpus acceptance

All 974 primary Rust tests, one child-process repeat, and 102 Python tests pass.
The 45 legacy semantic configurations and all 52 output-size gates also pass
without changing their baselines.
All 180 existing runtime configurations and nine controls pass, as do all 513
public configurations (468 development, 45 independent Rodux holdout). Their
source hashes, complete dataflow/fidelity results and full detailed sidecars are
unchanged. Runtime/public provenance, capture, emission and cold/warm artifact
cache gates pass at one and four threads.

Of 3,978 private source files, 3,977 are byte-identical, including 42 empty
placeholders. The only source change is
`ReplicatedStorage/DivergentVFX/LightningCore.luau`: `_update` loses one inferred
`local DISTANCE_EPSILON = 0.0001` declaration, and its five reads become `0.0001`.
Other same-spelled constants in sibling functions stay untouched. The shared
frame estimate declines this hoist conservatively; the old version of this
particular file also compiles. This is a readability tradeoff in the refusal
policy, not newly recovered source information or a demonstrated failure of
that old file.

The [corpus audit](../scripts/rehoist_corpus_audit.py) resolves the removed
binding to one parser declaration, requires no source origins, writes or
captures, replaces precisely its read tokens with the declaration's numeric
literal, and requires all remaining source bytes to match. It rejects any
additional edit. All 3,936 private recorded-name and capture contracts remain
equal; 3,935 full sidecars are identical. The changed file's whole-chunk input
dataflow result stays `unknown` before and after; recompilation and the exact
binding edit are separate checks. Across private/runtime/public data this gives
4,628 identical full sidecars out of 4,629, with all recorded contracts preserved.

Seven interleaved warm CLI rounds compare the preceding producer release with
the new release on all 3,978 private inputs. One-thread median is
17.317473 -> 17.382267 seconds (+0.37%); 16-thread median is
1.789713 -> 1.818294 seconds (+1.60%). Median peak RSS is
33,497,088 -> 33,796,096 bytes and 115,851,264 -> 115,896,320 bytes respectively.
Seven-sample nearest-rank p95 is the maximum: 17.519945 -> 17.426154 seconds
and 1.831979 -> 1.896599 seconds. Source is deterministic across all repetitions
and both thread counts, with exactly the reviewed file difference between
executables. These measurements report correctness cost and variation, not an
R7 speedup, allocation profile or OS cold-cache result.

The [validation inventory](roadmap_v2_acceptance/rehoist_validation.json) records
the immutable executable hashes, individual reports and measured cost. AI
remains disabled by default and R9 remains paused.
