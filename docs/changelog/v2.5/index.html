Tovek V2.5: our next era of faithful decompilation

Oct 2, 2026
8 min read

Tovek V2.5 fixes hundreds of ways decompiled Luau could quietly go wrong, rebuilds 2.6× as many inlined helpers, and writes code that reads closer to what people actually write.

  • On 2,700 freshly generated programs, V2.1.1 produced code that behaved differently 198 times. V2.5 got every one of them right.
  • Across four real Roblox games, 2.6× as many inlined helpers come back as calls.
  • 36% fewer anonymous locals: names now follow events, state and modules.
  • Faster at every thread count we measured, with new native builds for ARM64 Linux and Apple silicon Macs.

Today we’re releasing Tovek V2.5, the most accurate decompiler we have built. It brings together more than a hundred changes since V2.1, and almost all of them answer the same two questions: does the code Tovek writes do exactly what the original did, and does it read like something a person wrote?

V2.5 is available now for Windows and Linux, and for the first time as native builds for ARM64 Linux and Macs with Apple silicon. Like every Tovek release it runs entirely on your machine, with deterministic rules and no AI models.

Getting it right in real games

Test suites only go so far. For V2.5 we decompiled whole Roblox games from real dumps, 9,987 scripts in all, and fixed every place where the result failed to come out or behaved differently from the original. Each of those fixes is now a permanent test.

  • Loops that leave their parent. A break straight after an inner loop, or an inner loop that continues the outer one, used to stop Tovek from structuring the whole function. These now come out as the loops that were written.
  • Variables shared with closures. A value captured by a callback keeps its identity through swaps, copies and loops. V2.5 no longer folds a snapshot into the live variable, or loses a write made inside a loop.
  • The order things happen in. A call that can change a captured variable stays ahead of the code that reads it, table stores read their address at the moment Luau does, and library lookups that can raise an error keep their timing.
  • Scripts at Luau’s 200-local limit. Very large scripts keep their temporary values apart, so the output still compiles.
  • Scripts Roblox couldn’t compile. A script saved with a compile error holds only the compiler’s message. V2.5 writes that message as a comment, so the file is still valid Luau.
  • Values that only look the same. -0 and 0, empty slots in multiple returns, and the exact number of values a call passes on are all preserved.

V2.5 adds 91 new edge cases to the suite every release has to pass. V2.1.1 fails 28 of them (54 of 318 runs across three optimisation levels); V2.5 passes every one. In the four games we measured, 7 scripts or functions failed to decompile with V2.1.1; with V2.5, none.

Fuzzing for the bugs nobody reported

The bugs that matter most are the ones nobody notices: output that compiles, looks reasonable, and does something slightly different. To find them we generate random Luau programs that lean on the hardest parts of the language, compile each one at three optimisation levels, decompile it, and run the original and the decompiled program side by side.

On 2,700 fresh runs, from seeds never used while developing V2.5, V2.1.1 wrote a program that behaved differently 198 times, and V2 did so 212 times. V2.5 wrote none.

De-inlining, done properly

With -O2, Luau copies small local functions straight into the code that calls them. The call disappears and the helper’s body turns up again and again, in places nobody wrote it. Tovek has always tried to put those calls back. V2.5 is the first version that recognises most of the shapes the compiler actually leaves behind:

  • Helpers that hand back a value. Results that come from the helper’s own locals, its parameters, another call, or several values returned from different branches.
  • Helpers with a loop. When a helper returns from inside a loop, its inlined copy turns that return into a flag, a result variable and a break. V2.5 maps it back, so a ten-line search becomes one local item = findItem(…) again.
  • Searches that return early. An indexOf or contains that returns from inside a numeric for loop used to stop the whole script from decompiling once Luau inlined it. V2.5 decompiles it and puts the call back.
  • Copies the compiler trimmed. A copy specialised for its arguments can lose the helper’s opening branch. It still matches.
  • Constants the compiler folded. Call a helper with false and Luau drops every test of that argument from the copy, so visible and 0 or 1 turns into a bare 1. V2.5 works out which constant was passed and writes the call back as fade(frame, false).
  • Arguments that run code. An argument that Luau evaluates as the helper’s first step moves back into the call, at exactly the point where it ran.
  • The right helper, every time. Outer locals anchor a match, and when more than one helper could fit, the longest match wins.

Every rebuilt call is still checked against the helper’s body, the variables it captures, and the number of values it returns. When Tovek can’t prove a call is equivalent, it leaves the code exactly as it was. Across the four games, V2.5 rebuilds 4,260 helper calls, against 1,630 for V2.1.1.

How V2.5 measures up

We measured V2.5 against the two previous releases on the same inputs: a 3,978-script game from a live Roblox experience, three more real game dumps, the public libraries and generated programs from our standing benchmark, and the suites every release must pass. Where a lua.expert result is shown, it comes from the same frozen benchmark plan.

Code that reads like it was written

Being exact is only half of the job. V2.5 also takes a long step toward code you would happily keep open in an editor:

  • Names that come from context. A connection is named after its event (touchedConnection), Fusion builders take scope and use, reading a state value gives currentHealth, a getter keyed by name returns what the key says, a table of required modules becomes components, and a rebuilt call takes the name its helper returns, as in local track = loadTrack(animator, id).
  • Fewer temporaries. Stores after a call that returns several values become one assignment, a swap through a temporary folds back to a, b = b, a, and += now works on globals and on table fields reached through a local.
  • Cleaner control flow. A trailing guard becomes an elseif, a return shared by several branches is written once, an empty then becomes a negated condition, and two separate returns stay two returns instead of being fused into and/or.
  • Your choice of spelling. --style compact writes simple choices as if-expressions, and --assume-standard-libraries brings back math.pi, Vector3.new and friends when you know the script runs in a standard environment.

Across the four games, anonymous local declarations fall by 36% compared with V2.1.1, and generated parameter names by 16%. On the public libraries in our benchmark, the shape of the decompiled code is closer to the original source than any Tovek before it: a similarity of 0.887, up from 0.861 (lua.expert: 0.812).

Faster, on more machines

All of that extra checking could have made Tovek slower. Instead, V2.5 is faster: it keeps track of what it learns about each function far more compactly, skips work that wouldn’t change the result, and decompiles identical scripts in a folder only once. On one thread, the 3,978-script game takes 11.0 seconds, against 13.5 for V2.1.1; with every core busy it finishes in 0.87 seconds.

V2.5 also runs natively on two new kinds of machine: Linux on ARM64, from single-board computers to ARM cloud servers, and Macs with Apple silicon.

About Tovek

Tovek

Open-source Luau decompiler for Roblox

Tovek turns compiled Luau back into source a person can read: inlined helpers put back, names recovered from evidence, loops rebuilt. It runs locally with deterministic rules and is checked against Luau’s own parser, compiler and VM.
