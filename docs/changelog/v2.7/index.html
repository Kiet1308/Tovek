Introducing Tovek V2.7

We’re introducing Tovek V2.7, the newest release of our Luau decompiler. It gives back more of the functions Luau inlined than any release before it: across four real games, 9,623 helper calls come back as calls, 14% more than V2.6.1, and every one of the 9,987 scripts still decompiles.

V2.7 is also our most exact release. It decompiles all 1,023 edge-case runs and every executable review case correctly, where V2.6.1 got 58 and 93 of them wrong, and it gave no wrong output on 9,000 freshly generated programs.

Tovek V2.7 is available today for Windows, Linux and macOS, as a command-line tool and an HTTP server, and in your browser.

Giving back what the compiler took

Luau’s optimizer copies small local functions into the code that calls them. A decompiler reading that bytecode sees the copies, not the calls, and a script full of copies is long and hard to follow. Tovek’s job is to find each copy, prove it is one, and write the call the author wrote, without ever changing what the script does.

V2.7 rebuilds copies in places earlier releases could not reach: helpers whose return from a loop Luau turned into a store and a break, copies whose constants Luau folded through branches, locals and even math.pow, copies that sit inside other copies, copies split by a declaration the caller evaluated in between, and calls that forward their varargs. On the four real games that took rebuilt calls from 8,474 to 9,623, and on our 51-script research set from 645 to 658, against 509 for luacid.

It is also stricter about what counts as a copy. Where the bytecode’s own line numbers show that none of a helper’s code is in a function, a match there is code the author wrote by hand, and V2.7 leaves it as written.

De-inlining

Every rebuilt call is checked twice: its helper, specialized to the call’s constant arguments, must match the copy exactly, and evaluating the arguments first must change nothing the copy observed. Where Luau folded a constant, V2.7 folds the helper the same way before comparing; where a parameter is only tested for truth, the branch the copy kept tells its value.

The examples below are our own test scripts, compiled with Luau at -O2 and decompiled by V2.6.1 and V2.7. Rebuilt calls are marked.

Calls of find and total inlined into report, and report inlined into the chunk

View the source ↗

Each copy of find walks its path in a loop and stops at the first missing key; each copy of total sums until it passes 100. Luau turned their early returns into stores and breaks. V2.7 recognises those exits as returns, rebuilds all four calls, and then the call of report itself.

round(value, places) after Luau folded math.pow(10, places)

View the source ↗

With places constant, Luau computes math.pow(10, places) at compile time and the helper's first statement disappears from every copy. V2.7 solves the number back to its argument (10^places = 10000 gives 4) and rebuilds each copy as a call, whether it is returned, stored, or computed from an argument expression.

clamp(low, high, num) written as an and/or chain

View the source ↗

An a and b or c chain compiles to jumps that read like an if writing a local. V2.7 reads the chain back as the value it is, and every copy of clamp, with folded constants, stored into a caller's local or returned, is a call again.

onParameterChanged(kind, index, ...) called from handlers that forward their varargs

View the source ↗

A constant kind decides which branch each copy keeps, and the forwarded ... spreads into the helper's last parameters. V2.7 reads the constant off the branch taken and gives the spread back as ....

refreshDesired(state, key, value) with keys built from constants

View the source ↗

Given a constant key, the local holding `LastApplied{key}` is a constant too, and Luau folds it into every read. V2.7 specializes the helper the same way before comparing it with the copy.

Exactness

A decompiled script must do what the original did. Every edge case we have found since V2 is kept as a test: the script is compiled at -O0, -O1 and -O2, decompiled, compiled again and run, and its output must match. V2.7 passes all 1,023 runs; V2.6.1 passes 965.

  • Exact at the level you compiled. Output recompiled at the input’s optimization level behaves exactly like the input; at another level it follows that level’s rules, as the source would.
  • Tables keep their layout. A constructor keeps the allocation its bytecode had, so pairs visits keys in the same order, including explicit array keys beside record keys.
  • Reads keep their timing. A captured local read after a call that changes it, or an argument with side effects, stays where it ran.
  • Refusal over guessing. Hand-patched bytecode that no source can spell is refused, never printed as something else: 859 of the generated programs were patched that way, and all were refused.

Names and presentation

Names come from evidence in the script: what a value is read from, what it is passed to, what a function returns. V2.7 adds rules for rebuilt calls, running extremes, sets, collection elements, stored clock readings and documented Roblox APIs. Across the four games, generated names fell from 60,491 to 58,668, and output is 1.5% shorter.

Presentation follows the source: guard clauses, bottom-tested loops and one-shot loops read as they were written, do blocks keep their scope, self-updates print as x += 1, Roblox vector constants print as Vector3.new, and a value chain reads as a and b or c.

Speed and scale

V2.7 decompiles the four games in about the same time as V2.6.1: 43.4 seconds on one core and 3.55 seconds on all of them, within the noise of repeated runs. Several passes that grew quadratically on very long functions are now linear, and the HTTP server streams large batches and returns memory when idle, so thousands of scripts decompile without the server’s memory growing with them.

Availability

Tovek V2.7 is available today under the MIT license.

  • Command line: download luau-lifter for Windows x86-64, Linux x86-64, Linux ARM64 or macOS on Apple silicon. It decompiles one file or a whole folder in parallel.
  • Server: web-server, in the same download, decompiles over HTTP, one script or a batch at a time.
  • In your browser: drop a file on our site; it is decompiled on your machine and never uploaded.
  • Source: build it from GitHub.

Footnotes

  1. The four games are real Roblox games, 9,987 scripts in all. Their code is private; the page shows totals only. A rebuilt call is a call Tovek wrote in place of an inlined copy and marked with -- inferred equivalent call.
  2. Edge cases: 341 edge-case fixtures, each compiled at three optimization levels (1,023 runs). A run passes when the decompiled output, compiled again and run, prints exactly what the original prints.
  3. Review cases: 658 cases from our reviews, each compiled, decompiled, recompiled and run at the same level. V2.6.1 and V2.7 refuse 25 of them by design (hand-written bytecode no source can produce); V2.5.1 attempted them.
  4. Fresh programs: typed random programs from seeds never used in testing; for half the profiles the bytecode is patched the way only a hand-made chunk can be. A wrong output is one that, recompiled, behaves differently from the bytecode. 441 generated programs did not compile and are left out.
  5. Research set: 51 scripts, 14 of them public open-source modules. Similarity is a token-sequence ratio against the original source of 13 of those modules; luacid’s outputs are the ones saved with each sample.
  6. Speed: wall time over the four games on one Windows machine, releases run in alternation; the median of repeated runs. Runs of one binary vary by several seconds on one core.
